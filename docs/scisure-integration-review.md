# CATALYST / SciSure integration review — 0.8.0

Updated 19 September 2026. Scope: the Windows/macOS application, ingestion, normalization, consortium identities, saved-record reading and downloads, publication/retries, schema configuration, credentials, and packaging. The official API references and historical 0.7.0 findings below were recorded in the 12 September review; the 0.8.0 review checks the current implementation and synthetic API fixtures. The old Sites application is historical source, not the desktop runtime.

**Assessment:** the file/review connector now supports an explicitly entered SciSure HTTPS server, tokens stored separately by server, and user-selected downloads of individual attachments or complete verified review ZIPs. The sandbox remains the default. Scientific-source, saved-review, transfer, and stale-state checks have been strengthened. This remains a development release: no authenticated live SciSure requests or writes were performed in the 0.8.0 audit. Native inventory publication and Used/Generated links are unfinished; this release is not complete production integration for every datatype.

## Current 0.8.0 repairs and capabilities

See [the focused 0.8.0 audit notes](desktop-audit-0.8.md) for concrete findings, repairs, and regression suites. The current release preserves exact JSON/workbook numeric evidence, avoids treating cached formulas as observations, validates toolkit result completeness and physical ranges, accepts formatting-only spreadsheet cells, checks stored value/subject/time-axis consistency, rechecks changing remote records before success, and normalizes API IDs. Explicit downloads save only to a user-selected path; they do not introduce an automatic local research cache.

## Historical 0.7.0 repairs retained

| Area | Failure found | Repair and regression evidence |
| --- | --- | --- |
| GC precision | Toolkit conversions inherited the global decimal precision; extreme counts/exponents were insufficiently bounded. Embedded raw values were compared after float rounding. | Isolate arithmetic at 800-digit precision, bound numbers/counts, and compare original XLSX numeric evidence at lexical precision. Tests preserve long decimals, change the ambient precision, reject extreme counts, and detect raw values differing beyond float precision. Scientific calculations are not rerun. |
| GC context | Empty/negative producer mass and gas-reference settings could pass optional parsing. The declared source label could disagree with the toolkit catalyst label without a correction. | Require positive mass, interval and gas-reference conditions and nonnegative inlet flows. Require matching labels or explicit correction evidence. The entered 22.4-minute Rochester interval is retained; no global default is introduced. |
| Excel meaning | Date/time serials could become ordinary measurements. A stored fraction displayed as a percentage could be divided by 100 twice. Hidden cells and merges were not disclosed. | Recognize date/time and percentage formats, block incompatible interpretation, and warn about hidden/merged data or unavailable formats. Preserve originals; do not discard hidden rows or fill merged values. |
| Source integrity | A frozen Source still contained a mutable parsed dictionary; metadata copies shared parser state. | Snapshot parsed-artifact integrity, return independent metadata, and check source names, sizes and hashes. Tests reject changed parsed values and mismatched metadata. |
| JSON / names | API and saved JSON accepted duplicate keys, non-finite numbers and unsupported shapes. Table filenames had weaker validation than supporting files. | Share bounded strict JSON reading across API responses, reviews, tables, aliases and browsing. Reject duplicate keys, invalid Unicode, excessive nesting and numeric underflow. Apply portable filename limits consistently. |
| Saved review contracts | Checksum-matching packets could contain malformed approval, unknown schemas, unbounded source lists, mismatched mappings or invalid row/subject bindings. | Validate supported envelopes, approval/timestamps, artifact limits, context, lineage, normalization/profile and row bindings before trusting the record or fetching originals. Checksums remain integrity-consistency checks, not electronic signatures. |
| Receipts / retrieval | Metadata-only reads could overlook duplicate original filenames or conflicting ownership/hash metadata. Oversized originals were not always rejected before download. | Require one expected attachment per original; check IDs, names, sizes, owner when supplied, and recognized SciSure SHA-256 metadata. Verify downloaded bytes and state whether originals were actually downloaded/checksummed. |
| HTTP interruptions | Some truncated-response exceptions bypassed actionable transport errors; a short body could appear successful. | Check Content-Length and catch HTTP protocol interruptions. Writes remain uncertain until reconciled; no automatic duplicate POST is sent. Errors omit response bodies and credentials. |
| Pagination / scope | Duplicate detection could confuse a foreign user/sample ID with the record's own ID. Group changes near the end of a read could leave a stale result. | Use endpoint-specific IDs, reject duplicate paging parameters/invalid counters, and recheck group/destination after reads. Existing incomplete-page, changed-total and record-cap checks remain. |
| Existing catalog | Catalog reuse did not fully validate preexisting duplicate roots, conflicting procedures or missing completed lineage references. Untitled ordinary sections could break scans. | Validate complete visible lineage and pending identity reservations. Duplicate revision sections stop reuse; manifest-less sections are counted. Ignore unrelated untitled sections safely. A revision cannot silently move to a second publication destination. |
| Archived retries | A new session could treat an archived revision section as absent and recreate it. | Search archived sections before creating/reusing a revision. An archived or changed match pauses transfer for reconciliation. Existing sections/files are not overwritten. |
| Configuration / GUI | Sample-type detail IDs were not checked against the requested ID. Failed/disconnected sessions could retain stale connection indicators and remote views. | Verify native type identity before planning changes. Clear remote views and account/experiment selections; display connection failure while retaining in-session uncertain-write guards. |
| Build dependencies | The isolated environment used pip 25.0.1, with published advisories. | Upgrade to pip 26.2.1 and pin the CI upgrade. A new build-only advisory check blocks packaging if dependencies are vulnerable or incompletely checked. It sends public package names/versions to PyPI and never runs inside the application. |
| Bundled Python | The first CI build selected cached Python 3.12.10 rather than the patched interpreter used locally. Current 3.12 security releases have no Windows/Mac builds in the runner manifest. | Pin release packaging to Python 3.13.15 on all three platforms and enforce that version in the packaging script. Repeat native, scientific and packaged tests on the new runtime before release. |

Excel formatting can differ from the stored numeric meaning. See [Microsoft's date-system documentation](https://support.microsoft.com/en-US/Excel/date-systems-in-excel) and the [openpyxl number-format implementation](https://openpyxl.readthedocs.io/en/stable/_modules/openpyxl/styles/numbers.html). CATALYST does not import openpyxl or execute spreadsheet formulas.

## Datatype coverage

All six labs have distinct canonical namespaces. Synthesis origin, sample/model creator, acquisition, processing and submission labs remain separate. Sharing a procedure version does not merge batches. Physical derivatives have linked identities; computational models remain distinct from samples.

| Data | Available now | Boundary |
| --- | --- | --- |
| Reactor / GC | Explicit mappings; Rochester RWGS bundle import; original/source comparisons; calibration/flow context; separate nominal time axis. | Other reactions, pilot-scale conventions and partner exports need profiles and validation. No chromatographic integration, fitting or reaction calculations run here. |
| Synthesis | Batch/material/execution IDs, procedure versions, actual records/deviations, mapped quantities/names. | Native input/output inventory, multiple precursor relationships and protocol bindings are unfinished. |
| Spectroscopy / XRD / XAFS-XANES | Axis/signal mapping and technique-specific radiation, edge, reference, geometry and calibration context. | Vendor interpretation, alignment, background subtraction, Fourier transforms and scientific fitting are not performed. |
| TPR / TPD / TPO / CO uptake | Explicit axes or mass-normalized uptake units, pretreatment, gases and reference context; physical-value checks. | Integrations, adsorption models and site-count assumptions need validated processing methods. |
| Computation | Model IDs, supported physical-link declarations, software/input/method/environment/convergence evidence, explicit energy or quantity/value/unit mapping. | Partner parsers and method-specific conventions need validation; model links are declarations. |
| Images / native files | Unchanged images, PDFs, instrument exports, structures and other supporting bytes; imaging context or files-and-context-only review. | No OCR, image conversion, execution or AI interpretation. Embedded notebook-image retrieval and image thumbnails are not implemented. |

CSV, XLSX and flat-record JSON are the interpreted table formats. Preserving other files does not validate their scientific meaning. BET/adsorption, ICP and other new modalities need explicit context/profile extensions before being described as standardized; do not relabel them as unrelated techniques.

## Remaining limits and release gates

1. **Live server acceptance:** verify the intended server/account/group, native bindings, collaboration, unsigned/read-only behavior, and an approved synthetic upload/download with hash read-back, interruption, and permission rejection. Documentation and mocked responses cannot establish live permissions or tenant behavior. Enabling a server URL is not evidence that this deployment was tested against it.
2. **Native inventory is unfinished:** implement reviewed sample creation/reuse, required fields/quantities, published protocol bindings and Used/Generated links before promising integrated inventory. Schema installation alone does not enable them. See [the selected configuration](scisure-configuration.md).
3. **Recovery/concurrency is not atomic:** ordinary section/file calls are not a transaction or idempotency registry. Same-session unknown-write reconciliation is supported. After exit/crash, owners must reconcile incomplete SciSure records. Manual deletion, editing or permission changes can invalidate records. A new revision is not a substitute for reconciling an unfinished transfer.
4. **Visibility and size limits:** the catalog covers accessible CATALYST reviews in the active group, not inaccessible/native-only records or other groups. Limits are 250 reviews, 1,000 records per list, 1,000 browsable attachments, six originals, 20 MiB per file/review, 40 MiB combined originals, and 200,000 combined source cells. Large spectra/images and consortium-scale indexing need a reviewed streaming/index design. Limits fail explicitly.
5. **Identity boundaries:** shared tokens mean shared permissions, not independent reviewer authentication or partner isolation. An authorized account can replace both content and its hash. SciSure signing/audit controls remain authoritative. OS-vault storage follows the logged-in OS account's access rules; it does not protect against all code running as that user. See [keyring backend considerations](https://pypi.org/project/keyring/25.7.0/) and [SciSure signing](https://support.elabnext.com/hc/en-us/articles/36677169103508-Signing-Experiments).
6. **Distribution/old infrastructure:** EXE/DMG builds remain unsigned/not notarized. The sandbox is the default; another server must be supplied explicitly as an HTTPS DNS origin on port 443. Retire the earlier hosted prototype and any credential left there through owner controls; this audit does not claim decommissioning/revocation. The desktop creates no automatic research cache/database/log. Explicit downloads and their temporary save files use the location the user chooses. Unsent work remains in memory, subject to normal OS swap/crash behavior.
