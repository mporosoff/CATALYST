# CATALYST desktop

CATALYST runs on your computer and talks directly to SciSure. There is no hosted processing service, AI account, Cloudflare service, or research-data storage in GitHub. The default server is `https://sandbox.elabjournal.com`; enter your own SciSure server URL to use a token issued for that server.

## Open the application

Download the application from [GitHub Releases](https://github.com/mporosoff/CATALYST/releases). Access follows the repository's permissions.

- **Windows:** download `CATALYST-Windows.exe` and open it. It is one portable file, with no installer or separate Python installation. Do not use the older ZIP packages.
- **Mac:** download `CATALYST-Mac-AppleSilicon.dmg` for an M-series Mac or `CATALYST-Mac-Intel.dmg` for an Intel Mac. Open it, copy CATALYST to Applications or a user-owned folder, then open the copied app.

These are unsigned development builds, not publisher-signed or Apple-notarized releases. Institutional software approval may be needed. The Windows executable unpacks its bundled program libraries into a temporary folder while running; these are application support files, not a research-data cache. This is the standard [PyInstaller one-file behavior](https://pyinstaller.org/en/stable/operating-mode.html).

**Updates:** use **Get latest version** to open GitHub Releases. Finish or publish the current review, close CATALYST, and replace its application file with the new download. There is no dependency reinstall or background update. A saved OS credential is separate from the app and remains available. The download link sends no token or research information to GitHub.

The sidebar keeps **Add data**, **Review**, **Batch review**, **Saved records**, **Samples & data**, and **SciSure connection** within reach. In **Add data**, start with **What are you adding?** The form defaults to **Characterization / measurement data** with XRD selected. Choose the appropriate technique before linking a method. Fields marked **\*** are required for the chosen record type; optional details stay in a disclosure. The completion count and **Go to next missing field** help find incomplete entries. Validation checks the values and links when you create the review.

Hover over a field or its label, or focus the control with **Tab**, for its meaning and why it is needed. Press **Escape** to dismiss the explanation.

Use **Help · upload & access** to open a step-by-step guide that can stay open alongside the workspace. Choose **Upload data** for preparation, context, mapping, review, connection and transfer; choose **Access / download** for finding saved reviews, downloading packages or individual files, and reusing sample identities or mappings. **Previous** and **Next** move through one complete step at a time. The guide's action buttons open the relevant workspace page so you can follow the directions without losing your place.

Sample information, reusable procedures, and synthesis executions can be reviewed without attaching a file. Previews with blocking errors open on Validation. Saved records separates reviews, original files, and record details. Narrow windows retain scrolling and the submission action footer.

## Start from a sample (0.11.0)

**Samples & data** opens first. After connecting, use **Search / refresh**, select a sample, and **Open sample / data**. This combines saved CATALYST definitions with matching native inventory using exact identities. A local label is never enough to merge two samples. **Add measurement** or **Record synthesis** carries the selected identity into the upload form. **New sample** registers a material once.

The sample detail page lists explicitly linked records across experiments. **Open record details** shows the method, date, operator, files and standardized data. **Original tables** previews CSV, XLSX and flat JSON files with a file and worksheet selector; displayed tables are limited to 1,000 rows. **Download record + originals…** saves a verified package containing the full data. **Linked experiments** separately shows native Used/Generated relationships. Its attachment browser clearly labels files as experiment-level evidence, since a shared experiment does not establish which file belongs to which sample. Coverage notices distinguish failed or bounded searches from an empty database.

**Existing run** and **New run** on the upload form open the project/study/run chooser. A run is an experiment in SciSure. Several original files from one acquisition may be grouped into one record/run. Connected previews bind their chosen run; changing the current selection does not redirect older staged reviews. To move a staged record, edit it, select the intended run, rebuild and approve it. The batch table displays files, sample, procedure/version, and run together.

**+ Add new sample** and **+ Add new procedure** open short editors while retaining the original draft. The added definition is staged, still unapproved, before its dependent record. For a synthesis, enter the product label and description here; do not type an internal SMP identifier. A reusable procedure alone requires no sample. Existing native protocol versions are linked through **SciSure protocols…**.

For a native inventory sample, **Attach sample documents…** stores certificates, reference images and other supporting documents directly on the sample, with no experiment or method. Choose files, review their sample destination, then **Send documents**. Each upload creates a separate document group on that sample, preserving existing attachments without changing its shared sample type. **Sample documents…** lists and downloads these files. This route uses the account's sample and file permissions. Scientific measurements should use the run/method workflow instead. No new sample document is sent merely by selecting it.

Validation now presents readable issues with correction buttons. Choose an issue in **Review → Validation**, then **Choose or add sample**, **Choose procedure / method**, or **Go to field**. The app loads the right staged draft when necessary and focuses the relevant field. Other draft values and files are retained. Correct the value and rebuild/stage the preview; changes clear approval. Action failures also provide a navigation button for connection or inventory setup.

## Register once, then link each run

Choose the record that matches the work:

| What you are adding | Information entered once or for this run |
| --- | --- |
| **Characterization / measurement data** | Existing or inline new sample, matching procedure version, run date and operator, and the files. Historical measurements can explicitly select **Method not recorded**; the missing method stays visible in review. Add any changes from the method in notes. No synthesis history needs to be typed again. |
| **Sample information** | A recognizable label and description/composition. State, treatment, parent sample, and notes are optional. The app creates the sample's permanent ID. |
| **Reusable procedure / method** | Name, version, type, technique, and either instructions, an attached procedure document, or a document reference. |
| **Synthesis execution** | The registered product sample, saved synthesis procedure, execution date and operator, and optional deviations or supporting files. A procedure describes how to run it; an execution records that it was run. |
| **Computational results** | Saved computational procedure, model description and input structure, run date/operator, and results. Physical sample links are optional. |

Connect to the intended SciSure group and refresh the library to search existing samples and methods. The selectors search names, IDs and other saved details; method choices are filtered by type and technique. Selecting an existing record pins its exact saved review and checksum. Later measurements add dataset links and local aliases without changing the original sample definition.

If a definition is missing, use **+ Add new sample** or **+ Add new procedure** beside the selector. The current draft is held in memory while you enter the new definition. Choose **Stage this record** to put the definition in the batch and return to the original draft with its link filled in. Choices labeled **queued** have not yet been saved to SciSure. Put those definitions before their dependent measurements in the batch. New definitions and drafts can be prepared offline; selecting existing server records requires a connection.

**SciSure protocols…** reads published native protocol versions visible in the selected group, including protocols shared into that scope. Select a version and specify whether it is a synthesis, measurement, or computation method and its technique. This prepares a CATALYST procedure registration for review with an exact version reference. It does not edit, publish, or create a native SciSure protocol. Instructions and attached procedure files are saved in CATALYST experiment records.

## Reuse or register LIMS inventory

CATALYST saves reviewed scientific records in the selected experiment. For physical samples and their work, **Also register / link this sample in LIMS inventory** additionally requests native inventory creation/reuse and a Used/Generated relationship where applicable. Connected new samples default to native inventory; selecting a saved sample inherits its inventory setting. It does not add synthesis or measurement fields to the sample registration form. Supporting documents use the separate sample-only route described above.

Connect and **Verify selected destination** before preparing a native inventory review. To reuse a sample already in SciSure, choose **Search LIMS** beside the sample selector, or **Choose existing LIMS inventory sample…** on the sample form. Enter a search, choose **Search inventory**, inspect the matches, and use **Use selected sample**. The app prepares a reference to the selected sample for review and enables the inventory choice. An unfinished measurement draft is preserved while its sample registration is staged.

New native samples use **CATALYST Material v2**, which an administrator can prepare in the connection tools. Only the readable label and description/composition need to be typed: CATALYST supplies the canonical ID, creating lab and schema version. State/treatment and parent are optional. Reusing an existing native sample does not require converting it to v2, changing its metadata or creating a duplicate. Existing Material v1 types and samples remain intact; see [configuration and migration](scisure-configuration.md).

Before approving, inspect the review's inventory plan: the exact sample to create or reuse, its metadata, destination and any Used/Generated relationship. Sending applies only the reviewed plan and checks the result. Account permissions and external changes can block a plan even when the earlier read succeeded. A sample, procedure and the measurements referencing them can be staged together; definitions must come first and every record needs review and approval.

## Attach and review data

1. Choose the source lab, record type and technique, then fill the fields marked **\***. The default is to preserve original files with context. Add CSV, XLSX, JSON, native instrument exports, images, PDFs, structures, or logs. Original-file preservation needs no table mapping and performs no scientific interpretation.
2. For standardized table conversion, turn off the original-files-only choice and open **Column mapping & versions**. Choose the source file, worksheet and header row, then **Read columns**. Select canonical fields and source units; supply the source export/version, mapping name and version. Ignored columns remain in the original. Changing established rules requires a new version. Spectroscopy axis units must agree with the mapping. Optional exact name aliases use JSON such as `{"CO2":"carbon dioxide"}`.
3. For a Rochester toolkit RWGS bundle, select the original GC report XLSX, analysis XLSX, summary CSV and flows CSV together and choose the toolkit option. Its mapping checks cross-file relationships. An entered interval creates a separately documented nominal time axis; no default of 22.4 minutes is imposed on other runs.
4. Use **Stage this record** to retain the draft in **Batch review**, or **Review submission →** to review a single record. Inspect original filenames, sample and procedure links, validation, and any standardized values. Resolve errors, enter your reviewer name and note, acknowledge the review, then **Approve this revision**. Editing files, context, or mapping invalidates approval. Reprocessing retains the acquisition's dataset ID; a new measurement gets a new dataset ID.

## Review a batch before uploading

**Batch files…** creates one draft record per selected file using the currently selected sample, procedure, date and operator. A confirmation shows that these details will be shared. Use this only when those details apply to every selected file; edit individual records before approving. For several files belonging to one instrument run, mapped tables, or toolkit bundles, prepare the group together and use **Stage this record** instead.

In **Batch review**, use **Review selected**, **Edit**, **Remove**, and the ordering arrows to check every item. New sample and procedure definitions must appear before records that reference them. Approve each exact revision separately. **Send approved records** saves eligible approved records in order and stops at the first failure; records already marked **Saved & verified** are retained and are not automatically sent again. The queue holds up to 50 records and 200 MiB of retained files, parsed data and review content. Each record keeps the limits of six files, 20 MiB per file and 40 MiB combined. Drafts, approvals and the queue are held only in memory and are lost when the app closes.

**Spreadsheet checks:** Excel dates and durations can be stored as serial numbers. Export an explicit elapsed-time column with units before mapping those cells. Excel percentages are stored as fractions: choose **fraction** for a stored value such as `0.125` that Excel displays as `12.5%`. Hidden cells are included and disclosed; merged values are never filled into other cells. Blank formatting-only cells do not create extra columns. Exact source numeric text is retained; saved formula results do not become verified measurements. Toolkit checks flag impossible values, missing selected results, and inconsistent row roles. If the toolkit's catalyst label differs from your declared source label, record the reviewed correction in **Identity corrections / source-label notes**.

**Images and other original files:** Use **+ Supporting files** to attach PNG, JPEG, TIFF, other image formats, PDFs, native instrument exports, structures, or logs alongside a table. Files keep their original bytes, metadata within the file, filename, checksum, and submission's sample/dataset provenance. No image conversion, OCR, executable content, or AI analysis runs. This button also preserves nested JSON or arbitrary CSV/XLSX supporting documents without trying to interpret them as tables.

For image measurements, choose **imaging** and select the saved method containing the acquisition and scale information. Add run-specific conditions or scale limitations in notes. Preserve originals to review image files without a dummy table. This release verifies image bytes and provenance; it does not display image thumbnails, perform scientific image analysis, or infer scale from a filename.

## Connect and send

1. Sign in to your intended SciSure / eLabNext server in your browser. Open **Apps & Connections → Manage Authentication** and create an API token. For university SSO, SAML or two-factor authentication, use this in-product route after signing in; do not enter your university password in CATALYST. The token belongs to the server that issued it. See the [eLabNext API overview](https://developerdocs.elabnext.com/docs/overview).
2. In **SciSure connection**, enter **SciSure server URL**, then paste only the API token. CATALYST supplies the `Authorization` header; do not add `Bearer`, a header name or quotes. Use the server origin, for example `https://sandbox.elabjournal.com`, without a sign-in path or query. Only HTTPS DNS hostnames on standard port 443 are supported; redirects and IP-address URLs are not accepted. Changing the server clears the current token and connection. Optionally select **Remember** to keep the token in Windows Credential Manager or macOS Keychain. Otherwise it remains in application memory for the session. **Use saved token** and **Forget & disconnect** act on the selected server's saved credential.
3. Click **Connect**. Select an unsigned experiment in the intended group and click **Verify selected destination**. Use **Find existing run…** or **New run…** to select or create the experiment inside CATALYST. The chooser also offers reviewed project and study creation; new runs inherit their collaborators. Successful reads verify accessible account/destination information, not permission to write files, create inventory, or change schema. Those permissions are checked by SciSure when the corresponding operation is attempted.
4. In **Batch review**, choose **Send approved records** and confirm the displayed destination. For a single reviewed record outside the batch, use **Send / check transfer to SciSure** in **Review**. Source files and the approved record are uploaded into a revision-specific experiment section. Every file is downloaded and checksum-checked before the app records a completion receipt.
5. If the connection fails, keep the app open and inspect the transfer status. Sending stops before later batch records. An uncertain batch item is labeled **Check SciSure** and requires reconciliation; do not stage a duplicate. The single-record **Send / check transfer** action checks completed writes before another attempt. If a partial transfer has no review manifest, resolve the incomplete section in SciSure before starting another submission.

Anyone using a valid token can access the records and operations permitted to its SciSure account. A token does not grant access to every group or experiment. The app distinguishes a rejected/expired token from an operation denied by the account's permissions. No authenticated live SciSure verification was performed for this release; verify the intended account and destination with a synthetic submission before using real research data.

**Administrator tools:** Expand **Administrator tools · SciSure configuration** in the connection tab. **Prepare CATALYST material configuration** reviews the minimal Material v2 type and six metadata fields before any additions are applied; see the [selected configuration](scisure-configuration.md). Four metadata values are required: canonical ID, creating lab, description/composition and schema version. The app supplies all except the description. State and parent are optional. Installation is additive and leaves existing v1 types, fields and samples unchanged. **Inspect native SciSure setup (read only)** shows accessible sample types, required fields/quantities, account scope, collaborators, and optional sample/protocol references. Successful reads do not establish write permission. Schema preparation and inspection do not create research samples; sample creation and relationship writes belong to a separately reviewed submission.

Rate-limited reads have a bounded retry; a rejected write can be retried manually after the displayed delay. An unknown write retains its duplicate-write guard even after reconnecting within the same app session. Recovery after closing/crashing the app is still manual: inspect and reconcile incomplete records in SciSure. **Reuse mapping / revise** creates a new revision; it does not resume the old transfer.

The API's maximum of 1,000 results per page is a pagination limit, not a limit on the number of records in your LIMS. CATALYST retrieves pages automatically and separately bounds each list to 1,000 records and its CATALYST catalog to 250 reviews. If the app reaches a limit or cannot read a complete list, it stops with an explanation rather than treating partial results as the full database.

## Read existing data

Connect and select an experiment, then open **Saved records**. **List saved reviews** shows desktop review packages, including incomplete transfers. **Open review** reads the standardized data and history into memory. **More actions → Load review + originals** additionally retrieves and verifies original files. **More actions → Reuse mapping / revise** prepares a new revision linked to the saved one; the previous approval does not carry forward.

To save a complete review to your computer, select it under **Saved reviews**, choose **More actions → Download review package…**, and choose a ZIP filename. The app downloads and verifies all original files before saving. The ZIP includes the approved review with its mapping, units, context, and provenance; the completion receipt; exact standardized JSON; a convenience CSV when standardized rows exist; and unchanged originals. Toolkit CSVs put each quantity in a separate column labeled with its field and unit; the JSON retains the full nested evidence. Incomplete transfers cannot be exported as complete packages. Spreadsheet software may infer types when opening CSV; use the JSON and original files when exact values matter. Text that could be interpreted as a spreadsheet formula receives an apostrophe prefix in the convenience CSV only.

The status distinguishes checking review/receipt metadata from downloading and verifying every original checksum. Duplicate, missing, oversized or inconsistent attachments pause the read. Archived revision sections are not recreated automatically during a retry. These checks do not make an approval an authenticated electronic signature.

In **Original files**, **Browse attachments** lists FILE/FILES/CUSTOM section attachments, including Office Online files not created by CATALYST. File ID, previous file ID, and stored date distinguish same-name revisions; newest IDs appear first. **Download…** saves the selected attachment to a location you choose after checking its section membership and current metadata. **Read selected file** shows CSV/XLSX/JSON content in memory; other file types show receipt/size information. Embedded notebook images, legacy Excel sections, canvas drawings, and protocol attachments use other endpoints and are not included. Signed experiments can be read. eLABHybrid files remain accessible through SciSure; this release does not contact the separate institutional file host.

## Where information lives

- Existing source files stay in their original location. Individual attachment downloads and review ZIPs are written only when you choose a save location. A save uses a temporary file in that folder and replaces the selected destination after the complete write succeeds. The app creates no automatic research-data cache, database, or research log.
- Working files, previews, and unsent approvals live in memory and are lost on exit. The operating system manages process memory; this is not a forensic guarantee against swap or crash dumps.
- SciSure stores the transferred original files, review/mapping/context/provenance package, approval statement, IDs, and completion receipt.
- Optional tokens are stored separately by server in the operating system credential store. They are never put in GitHub, packaged code, research manifests, or download packages.
- Shared tokens use the same SciSure account and permissions for everyone. CATALYST reviewer names are self-reported, not independent authenticated signatures. Native SciSure signing and permissions remain authoritative.

This release imports toolkit scientific results; it does not execute or reproduce the GC processor. Technique and computational paths support explicit table mappings and contextual validation, not scientific fitting or calculation engines. Partner-specific profiles require representative data and review. The shared catalog covers completed CATALYST packages visible to the token in its active SciSure group, up to 250 reviews. The separate native protocol reader loads up to 250 published versions visible in that group scope. Connected new samples and chosen native samples include native inventory in the review by default; cross-group CATALYST catalogs are not implemented. Older saved CATALYST reviews remain readable with their original validation rules and do not acquire new native writes automatically. No authenticated live SciSure verification is claimed for the adaptive workflow, native inventory or native protocol reader; testing uses synthetic endpoints and records.
